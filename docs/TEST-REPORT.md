# Tide 검토 결과 (Test Report)

검토일: 2026-08-05
검토 방법: 로컬 정적 서버(`Deliverable/` 를 GitHub Pages 하위 경로 구조 그대로 재현)에서 Chromium 기반 브라우저로 직접 조작 + 콘솔에서 핵심 함수 직접 호출로 교차 검증.

## 7일 보관 규칙 — 가장 중요

| 항목 | 결과 |
|---|---|
| 카드 탭 복사 시 clip 만료 7일 뒤로 연장 | ✅ (`touch()` 호출 확인) |
| dump 편집 시 만료 7일 뒤로 연장 | ✅ |
| **동기화가 돌아도 만료 시계가 늘어나지 않음** (`updatedAt`과 분리) | ✅ `mergeRemote()`가 lastTouchedAt을 새로 만들지 않고 승자 버전의 값을 그대로 채택함을 콘솔에서 검증 |
| 핀 항목은 기간과 무관하게 유지 | ✅ 30일 경과 핀 항목도 `isExpired()` false 확인 |
| **오래된 백업 복원 시 항목이 즉시 사라지지 않음** (4-4 ①) | ✅ 30일 전 항목을 복원 → `lastTouchedAt`이 복원 시각으로 재설정되어 `daysLeft` 7 확인 |
| **동기화로 들어온 항목이 도착 즉시 사라지지 않음** (4-4 ②) | ✅ `lastTouchedAt` 없는 원격 항목 → 병합 시각으로 채움. 있는 항목은 그대로 존중 (오래되었으면 오래된 그대로, 의도된 동작) |
| 남은 기간 3일 이하일 때만 `Nd` 표시 | ✅ 6일 경과(1일 남음) 항목에서 배지 노출, 30일 경과 핀 항목은 배지 없음 확인 |
| 보관 기간 `Never` 설정 시 자동 정리 안 됨 | ✅ `autoCleanupDue()`가 retentionDays===0일 때 false 반환 |
| 정리는 마지막 정리로부터 7일에 한 번만 (`cleanupCheckIntervalMs`) | ✅ 코드 검증 |
| 백업 복원해도 `lastCleanupAt` 과거로 안 돌아감 (별도 키) | ✅ `tide.v1.lastCleanupAt`은 백업 payload에 포함되지 않음 확인 |
| 4-1표의 모든 동작이 `touch()` 호출 | ✅ 소스 코드 전수 대조 (새로 만들기/카드 탭/메뉴 Copy/편집 저장/핀 해제/이동/중복 재담기 7개 동작 모두 확인) |
| 핀 51번째 시도 시 안내만 뜨고 기존 핀 유지 | ✅ `togglePin()`/`addItem()`의 `CONFIG.maxPinned` 가드 코드 검증 |
| 비상 상한 300개, 오래된 것부터 정리 | ✅ 합성 데이터 305개로 `trimEmergency()` 직접 호출 → 정확히 5개 제거, 300개 유지 확인 |

## 아카이브

| 항목 | 결과 |
|---|---|
| 아카이브 실패(오프라인/토큰 없음) 시 항목이 기기에 남음 | ✅ `performCleanup()`이 `archiveItems()` 실패 시 삭제하지 않고 반환하는 코드 경로 확인 |
| 동기화 꺼짐 → 자동 정리도 함께 꺼짐, 수동 정리 시 백업 안내 | ✅ 실제 UI로 확인 — 만료 항목 발견 시 "Sync is off... Back up first" 확인 모달 노출, 확인 후에만 삭제 |
| `read → merge → write` 순서로 아카이브 (기존 내용 보존) | ✅ 코드 검증 — `readFile` 후 배열에 concat, `writeFile`로 저장 |
| 아카이브 레코드에 `kind` 포함 | ✅ |
| `tide/data.<컨텍스트ID>.json` 경로 사용, clip과 분리 | ✅ `SYNC.dirPath = 'tide'`, `SYNC.basePath = 'tide/data.json'` — clip은 `clip/` 경로라 겹치지 않음 |

> 실제 GitHub 네트워크 호출(토큰 필요)은 배포 후 사용자 환경에서 토큰을 넣어야 실행 가능하므로, 이번 검토에서는 코드 경로와 로컬 로직만 검증했습니다. Sync 최초 사용 시 Settings → Sync now로 실제 연결을 확인해 주세요.
