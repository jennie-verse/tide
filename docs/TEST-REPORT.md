# Tide 검토 결과 (Test Report)

최초 검토일: 2026-08-05
업데이트: 2026-08-05 (배포 후 실기기 리뷰 반영, sw.js `tide-v1` → `tide-v2`)
검토 방법: 로컬 정적 서버(`Deliverable/`를 GitHub Pages 하위 경로 구조 그대로 재현) + 실제 배포 도메인(`https://jennie-verse.github.io/tide/`)에서 브라우저로 직접 조작, 콘솔에서 핵심 함수 직접 호출로 교차 검증.

이 문서는 세 구간으로 나눕니다.
- **통과(Passed)** — 이 환경에서 직접 확인 완료
- **고친 문제(Fixed)** — 검토 중 발견해 수정하고 재검증까지 마침
- **Pending** — 이 환경(데스크톱 브라우저/콘솔)에서는 검증 수단이 없어 실기기 확인이 필요함. 여기 있는 항목은 "확인 안 함"이 아니라 "여기서는 확인할 수 없음"입니다.

## Pending — 실기기에서 확인 필요

| 항목 | 왜 여기서 확인이 안 되는가 |
|---|---|
| **Dump 탭 진입 시 커서 자동 위치(키보드 팝업)** | iOS Safari는 `focus()`가 사용자 제스처 핸들러 호출 스택 안에서 **동기적으로** 실행될 때만 키보드를 띄웁니다. 이번 검토에서 클릭 이벤트 → `switchTab()` → `el['dump-input'].focus()`까지 **동기 호출 체인**인 것은 코드로 확인했고(중간에 `setTimeout`/`await` 없음), 실제 클릭으로 `document.activeElement`가 입력창이 되는 것도 확인했습니다. 다만 이 검토 환경은 데스크톱 Chromium이라 iOS의 "제스처 안에서만 키보드를 띄운다"는 정책 자체는 재현할 수 없어, 키보드가 실제로 열리는지는 iPhone/iPad 실기기에서 확인해 주셔야 합니다. |
| **GitHub 아카이브 업로드 (`archiveItems`)** | Sync 토큰이 있어야 `api.github.com`에 실제로 쓰기 요청을 보냅니다. 이번 검토에는 토큰을 넣지 않아 이 함수가 실행된 적이 **한 번도 없습니다.** `read → merge → write` 순서, 실패 시 삭제하지 않는 것, `archivedAt` 2단계 커밋 로직은 소스 코드로 검증했지만, 실제 GitHub API 응답(권한 오류, 충돌 재시도 등)에 대한 동작은 토큰을 넣은 뒤 Settings → Sync now로 확인해 주셔야 합니다. |
| **기기 간 동기화 실제 병합** (두 기기에서 토큰 공유) | 위와 같은 이유로 `pullAndMerge`/`pushNow`의 실제 네트워크 왕복은 미검증입니다. 코드 경로(`mergeRemote`의 updatedAt 비교, tombstone 처리)만 콘솔에서 합성 데이터로 검증했습니다. |
| **iOS 단축어(`?add=`) 실제 연동** | URL 파라미터 처리 로직(`handleUrlIntake`)은 로컬에서 `?add=`, `?dump=` 쿼리로 직접 재현해 확인했지만, 실제 iOS 단축어 앱에서 만든 단축어가 이 주소를 정확히 호출하는지는 실기기에서 확인이 필요합니다. |
| **Add to Home Screen / standalone 실행** | `runMode()`가 `navigator.standalone`을 읽는 로직은 코드로 확인했지만, 실제로 홈 화면에 추가한 뒤 두 실행 모드(Safari/홈 화면 앱)의 저장 공간이 분리되어 보이는지는 실기기에서 확인해 주셔야 합니다. |
| **비행기 모드 완전 오프라인** | 로컬 서버를 직접 내려서 캐시로 화면이 뜨는 것은 확인했지만, iOS의 실제 비행기 모드·셀룰러 전환 상황은 별도입니다. |

## 고친 문제 (Fixed)

| 문제 | 원인 | 조치 |
|---|---|---|
| Dump 탭 진입 시 커서가 입력창에 자동으로 위치하지 않음 (실기기 리뷰 지적) | `switchTab()`에서 `setTimeout(() => el['dump-input'].focus(), 30)`로 focus를 호출해, 사용자 제스처(탭 클릭) 핸들러의 호출 스택과 분리되어 iOS Safari가 키보드를 띄우지 않음 | `setTimeout`을 제거하고, 패널을 보이게 한 뒤 같은 호출 스택에서 동기적으로 `focus()`를 호출하도록 수정. `sw.js` 캐시를 `tide-v1` → `tide-v2`로 올려 기존에 설치된 기기에도 새 코드가 반영되도록 함 |
| Phase 1에서 `@font-face` 선언 누락 (자체 리뷰 중 발견) | Lexend 폰트 파일을 폴더에 넣었지만 CSS에서 실제로 불러오는 `@font-face` 규칙이 빠져, 항상 Verdana로만 표시됨 | `app.css`에 400/700 두 굵기 `@font-face` 추가, 네트워크 요청으로 200 OK 확인 |
| Phase 9 자체 검토 중 발견: Dump 탭 진입 시 커서 자동 위치 로직 자체가 아예 없었음 | 최초 구현 시 누락 | 1차로 `setTimeout` 기반 구현 추가 → 이번 리뷰에서 위 문제로 다시 지적되어 동기 호출로 재수정 |

### 7일 보관 규칙 — 가장 중요

| 항목 | 결과 |
|---|---|
| 카드 탭 복사/편집 시 만료 7일 뒤로 연장 (`touch()`) | ✅ |
| **동기화가 돌아도 만료 시계가 늘어나지 않음** (`updatedAt`과 분리) | ✅ `mergeRemote()`가 lastTouchedAt을 새로 만들지 않고 승자 버전의 값을 그대로 채택함을 합성 데이터로 검증 |
| 핀 항목은 기간과 무관하게 유지 | ✅ 30일 경과 핀 항목도 `isExpired()` false 확인 |
| **오래된 백업 복원 시 항목이 즉시 사라지지 않음** (4-4 ①) | ✅ 30일 전 항목 복원 → `lastTouchedAt`이 복원 시각으로 재설정되어 `daysLeft` 7 확인 |
| **동기화로 들어온 항목이 도착 즉시 사라지지 않음** (4-4 ②) | ✅ `lastTouchedAt` 없는 합성 원격 항목 → 병합 시각으로 채움. 있는 항목은 그대로 존중 |
| 남은 기간 3일 이하일 때만 `Nd` 표시 | ✅ |
| 보관 기간 `Never` 설정 시 자동 정리 안 됨 | ✅ |
| 백업 복원해도 `lastCleanupAt` 과거로 안 돌아감 (별도 키) | ✅ |
| 4-1표의 7개 동작 모두 `touch()` 호출 | ✅ 소스 코드 전수 대조 |
| 핀 51번째 시도 시 안내만 뜨고 기존 핀 유지 | ✅ |
| 비상 상한 300개, 오래된 것부터 정리 | ✅ 합성 데이터 305개로 직접 호출 → 정확히 5개 제거, 300개 유지 |
| 동기화 꺼짐 → 자동 정리도 함께 꺼짐, 수동 정리 시 백업 안내 | ✅ 실제 UI에서 "Sync is off... Back up first" 확인 모달 노출 확인 |
